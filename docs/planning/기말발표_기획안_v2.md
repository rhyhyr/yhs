# YHS 기말 발표 기획안 v2 (예시 덱 스타일 + 코드 검증 + 교수·선배 피드백 반영)

> **보존 문서 — 발표 기획안 v2.** 발표 준비 시점의 기록이다.
> 문서에 인용된 수식·임계값은 작성 당시 값이다. 현재 값은
> [backend/config/retrieval.yaml](../../backend/config/retrieval.yaml).


> 목적: CcTv(탄소) 팀의 잘 만든 예시 덱 3종에서 **검증된 슬라이드 패턴**을 추출하고,
> 그 위에 YHS(유학생 비자 RAG) 내용을 얹어 **발표용 PPT 제작 기획안**을 재작성한다.
> v1 대비 변경점: ① 예시 덱의 시각 패턴을 슬라이드별로 명시, ② 코드와 어긋났던 수식·임계값·캐시 표현을 정정,
> ③ 선배가 "필수"라 한 서브그래프 추출 그림을 핵심 슬라이드로 승격.

## 0. 예시 덱(CcTv)에서 가져올 디자인 DNA

세 PDF는 전부 같은 팀의 탄소 프로젝트 덱이다. **내용이 아니라 형식**을 본다.

**공통 크롬(모든 슬라이드)**
- 왼쪽 세로 컬러 바(CcTv=초록). **YHS는 파랑 계열로 통일** (중간발표가 이미 파랑).
- 상단 헤더: 좌측 "실증적SW개발 프로젝트 I / 기말발표", 우측 팀명 "YHS". 하단 좌측 페이지 번호.
- 섹션 제목: **굵게, 문장형, 밑줄 한 줄.** 부제는 그 아래 작은 박스(예: "기존 연구", "진행한 연구").

**검증된 슬라이드 패턴 (그대로 차용)**
| 예시 위치 | 패턴 | YHS에서 쓸 곳 |
|---|---|---|
| 팀 소개(슬2) | 인물 3카드 → 화살표 → 프로젝트 한 줄 | 생략 가능(시간) 또는 표지에 흡수 |
| 문제정의(슬5) | **배경을 흐리게 깔고 핵심 문장 1개만 박스로 강조** | S2 한 문장 메시지 |
| 아이디어(슬6) | **3단계 흐름 + 각 단계 미니 그림 + 화살표** = "전체 흐름 간단히" | S4 통합 파이프라인(간단 버전) |
| 기존연구/진행연구(슬6→7→8) | **같은 레이아웃을 회색→강조로 토글** = as-is/to-be | S6~8 문제별 as-is/to-be |
| 실험결과(슬10) | **차트 1개 + 실험/분석 컬러 카드 + 헤드라인 숫자 크게(빨강)** | S9 성과, S6~8 before/after |
| 기대효과(슬12) | 3열(환경/경제/사회) → 하단 배너 1줄로 수렴 | S11 결론 |
| 데모(슬9 영상) | 화면 녹화 1개 풀스크린 | S10 데모(선택) |
| Q&A(슬13) | 큰 "Q & A" + 감사 | S12 |
| Appendix(슬14~) | 문제 정의서 원본 첨부 | 부록: 평가셋·임계값 스윕표 |

**숫자·강조 규칙(예시의 핵심 강점):** 슬라이드마다 **헤드라인 숫자 1개를 빨강으로 크게**(예: "12.8% 절감"). 본문은 짧게, 키워드만 색. → 교수 ②(숫자 넣기) + ③(글자 크게)를 동시에 만족.

**단, 예시를 따라 하면 안 되는 것 1개:** Fairday 슬3은 한 장에 사진 3장 → 교수가 YHS에 "한 슬라이드 사진 여러 장 금지"라고 명시. 배경 슬라이드는 **아이콘/도형 + 짧은 텍스트**로, 사진은 장당 1개 이하로.

## 1. 전체 흐름 (피드백 ⑫⑬ + 선배 메모 반영)

### 서사의 척추 (v1에서 수정)
v1은 전체를 "3대 벽을 수치로 해결"(개선 스토리)로만 짰다. 그러나 **선배 메모**가 다른 축을 요구한다:
> "핵심 방법은 예시 위주로 자세히. 예) '사하구','취업' NER → KG 기반 RAG 검색으로 **SubGraph 추출**. **PPT로 그린 그림 필수.** 원리 설명 O. 핵심 아닌 방법은 간단히('NER로 추출함. 끝')."

→ **두 축을 합친다:** (A) 핵심 메커니즘(서브그래프 추출)을 그림으로 또렷이 설명 + (B) 중간발표 이후 측정→분석→변경을 as-is/to-be로 증명. v1은 (B)만 있고 (A)가 없었다 — 이게 가장 큰 누락.

### 한 문장 메시지
> "중간발표 땐 **설계**가 끝났다고 봤다. 실제로 돌려보니 운영에서 3개의 벽이 나왔고, 각각을 **수치로 분석해 구조를 바꿔** 해결했다. 그 중심엔 **관계 그래프에서 서브그래프를 뽑아 근거로 쓰는** 검색 방식이 있다."

### 15분 슬라이드 배치 (≈12장)
| # | 슬라이드 | 시간 | 예시 패턴 | 역할 |
|---|---------|------|----------|------|
| 1 | 표지 | 0:20 | 중간발표 표지 재활용 | - |
| 2 | 문제인식 + 페르소나(압축 1장) | 1:00 | 문제정의 흐림+강조박스 | 빠른 리캡(⑫⑬) |
| 3 | 중간발표 시점 = "설계의 이상" | 0:50 | 3단계 흐름 미니 | 출발점(⑬) |
| 4 | **핵심 방법: 서브그래프 추출** ★ | 2:00 | 아이디어 흐름 그림 | 선배 "필수" 그림, 원리 O |
| 5 | 실제 운영 3대 벽(+as-is 수치) | 1:00 | 실험/분석 카드 | 척추(②⑪) |
| 6 | 벽1 → 분석 → 해결: 검색 품질 | 1:40 | as-is/to-be 토글 | ⑤⑥⑦⑧ |
| 7 | 벽2 → 분석 → 해결: 다국어 비용 | 1:20 | as-is/to-be 토글 | ⑥⑧② |
| 8 | 벽3 → 분석 → 해결: 실시간 수집 | 1:20 | as-is/to-be 토글 | ⑥⑧② |
| 9 | 정량적 성과 종합 ★ | 2:00 | 차트+카드+빨강 숫자 | ②⑪⑤ |
| 10 | 차별화 / (선택) 데모 | 1:00 | 비교표 또는 영상 | ⑪ |
| 11 | Lesson & 결론 | 1:20 | 3열→배너 수렴 | ①⑩ |
| 12 | Q&A / 감사 | 0:10 | 큰 Q&A | - |

합계 ≈ 14분. (글자 크게 ③ 하면 장당 정보량 자동 축소 — 이 배치가 그걸 가정)

**v1 대비 핵심 변화:** 'S4 핵심 방법(서브그래프 추출)' 신설, 'S8 통합 파이프라인'은 S3로 흡수(간단 흐름만), 문제별 슬라이드 3장은 예시의 as-is/to-be 토글 패턴으로 통일.

## 2. 슬라이드별 구성안 + 발표 멘트

각 슬라이드: **[넣을 것]** / **[예시 패턴]** / **[멘트]** / **[반영]**

### S1. 표지
- [넣을 것] 제목 "실증적SW개발 프로젝트 I — 기말발표", 팀 YHS, 팀원, 날짜. 부제 한 줄 "중간발표 이후 개선 보고".
- [예시] 중간발표 표지 레이아웃 그대로(파랑).
- [멘트] "팀 YHS입니다. 오늘은 중간발표 이후 실제 운영하며 마주친 문제를 수치로 분석해 해결한 과정을 보여드리겠습니다."

### S2. 문제인식 + 페르소나 (압축, 1장)
- [넣을 것] 흐린 배경 위에 핵심 문장 1개 강조 박스: "유학생 행정 정보는 기관별로 흩어져 있고, 비자→취업→절차로 **종속**된다." 우측 하단 미니 페르소나 카드(Li Wei, 23세/중국/거주 6개월/한국어 약함).
- [예시] Fairday 슬5 "흐림+강조 문장" 패턴.
- [멘트] "문제는 중간발표에서 정의했습니다. 한 줄로, 정보가 흩어져 있고 단순 FAQ가 아니라 강한 종속 관계를 가집니다. 기준 사용자는 거주 6개월차 Li Wei입니다." (이미지 분산 금지 ③ 준수)
- [반영] ⑫(빠르게), ⑬

### S3. 중간발표 시점 = "설계의 이상" (전체 흐름 간단히)
- [넣을 것] **간단 흐름 1개만**: `문서 → 그래프 구축 → [FAQ→Fast→Deep→웹] 라우팅 → 답변`. Neo4j는 **한 줄**로만(④). 하단 "이 정도면 다 커버할 줄 알았으나…".
- [예시] Fairday 슬6 3단계 흐름(미니 그림+화살표).
- [멘트] "중간발표 땐 그래프 적재, FAQ·Fast·Deep·웹 라우팅까지 **설계상으론** 다 됐습니다. 전체 흐름은 이게 전부고, 지금부터 각 단계를 하나씩 자세히 보겠습니다." (교수: 전체 파이프라인은 간단히만)
- [반영] ⑬, ④, 교수("전체는 간단, 단계는 자세히")

### S4. ★핵심 방법: 서브그래프 추출★ (선배 "필수" 그림)
- [넣을 것] **Input→Output 그림** (선배 예시 그대로):
  1. 질문 "사하구에서 아르바이트 가능?" →
  2. NER/엔티티 링킹으로 `[사하구][아르바이트]` 추출 ("NER로 추출함" 정도로 간단히 — 선배 지시) →
  3. 그래프에서 해당 엔티티를 앵커로 잡고 →
  4. **DDE 멀티홉으로 연결된 SubGraph 추출**(비자조건·필요서류·BLOCKS 노드/엣지를 색으로) →
  5. 그 서브그래프가 답변 근거.
- [예시] Fairday 슬6 아이디어 흐름 + 강조색.
- [멘트] "핵심은 단순 텍스트 검색이 아니라 관계 그래프에서 **근거 덩어리(서브그래프)를 통째로 뽑는** 겁니다. 질문에서 핵심어를 뽑아(NER) 그래프의 엔티티에 연결하고, 거기서 가까운 노드들을 홉 거리로 따라가 비자조건·서류·차단조건까지 한 묶음으로 가져옵니다. 이게 일반 RAG와 다른 지점입니다."
- [근거 그림은 별도 제작 필요 — Claude에게 요청 가능.]
- [반영] 선배 메모(핵심방법 자세히·그림 필수·원리 O), ⑥, ⑪

### S5. 실제 운영 3대 벽 (+as-is 수치)
- [넣을 것] 3행 표, 각 행에 **as-is 숫자 1개**(실측 채울 것):
  - 검색 품질: "데이터 N배 → 유사도 평준화 → 정답 chunk 변별 실패" `[정답 chunk가 top-k에 든 비율 ___%]`
  - 다국어 비용: "구어체·오타로 매번 번역 LLM 호출" `[쿼리당 번역 호출 ___회]`
  - 실시간 수집: "JS 동적 렌더링으로 정적 수집 실패" `[정적 requests 성공률 ___%]`
- [예시] 실험/분석 컬러 카드(슬10) 축소판, 숫자 빨강.
- [멘트] "운영에 올리자 3개의 벽이 나왔습니다. 검색 품질, 비용, 실시간 수집. 각각 **숫자로 먼저 측정**하고 그 분석으로 구조를 바꿨습니다."
- [반영] ②, ⑪, ⑥

### S6. 벽1 → 분석 → 해결: 검색 품질 (DDE + 하이브리드 재랭킹)
- [넣을 것] **as-is/to-be 토글**:
  - 문제(예시): "'아르바이트 가능?'에 데이터가 늘자 무관 chunk가 상위로."
  - 분석: 임계값 스윕 → 최적점 채택. **N=___ 검증셋에서 산출** 명시(⑤).
  - 해결(How): DDE(홉0=1.0, 홉1=0.5, 홉2=0.25, 홉3=0.125) + 병합 재랭킹.
- [수식 — ⑦, **코드 검증 정정**] 슬라이드엔 **병합 재랭킹 식 하나만**:
  - `Score = 0.60·S_base + 0.30·S_keyword + 0.10·S_recency`
  - 한 줄 해설: "S_base=그래프/벡터 후보의 기본 점수(주력 0.6), S_keyword=정확 키워드 일치(오타·공백 보정 0.3), S_recency=최신 공지 가중(0.1)."
  - ⚠️ **주의(코드 사실):** 코드엔 식이 2단계로 존재 — 벡터 내부식 `0.65·cosine+0.25·kw+0.10·rec`와 병합식 `0.60/0.30/0.10`이 다르다. 발표엔 **병합식만** 쓰고 "후보를 합칠 때의 최종 재랭킹 식"이라 라벨. `S_base`를 "벡터유사도"라고만 부르면 0.65 식과 충돌하니 금지. 중간발표의 `0.6/0.4` 2항식은 현재 코드에 없음 → 폐기.
- [멘트] "첫 벽은 검색 품질입니다. 데이터가 늘자 점수가 위로 평준화돼 엉뚱한 chunk가 1순위로 왔습니다. 검증셋으로 임계값을 스윕해 컷을 정하고, 홉 거리로 점수를 감쇠시키는 DDE에 키워드·최신성을 더한 재랭킹을 넣었습니다. 결과는 [정확도 __%→__%]."
- [반영] ⑤⑥⑦⑧②

### S7. 벽2 → 분석 → 해결: 다국어 비용 (번역 캐시)
- [넣을 것] CPU 캐시 그림 **삭제**. 실제 흐름: `처음 보는 표현 → LLM 1회 번역 → 세션 캐시에 저장 → 동일 표현 재호출 0회`. before/after 숫자 박스.
- [⚠️ 표현 정정 — 코드 사실] 코드의 캐시는 `{질문원문: 번역문}` **세션 메모리 캐시**다(프로세스 끄면 소멸). 단어→사전(ALIASES_MAP) 동적 추가하는 "자가학습 사전"은 **없다**. → "자가학습 사전"이라 하지 말고 **"세션 내 번역 메모이제이션"**으로. 비용 절감은 "같은 세션 반복 질문"에 한정해 정직하게. (영속 사전을 실제 구현하면 그때 "자가학습"이라 부를 것.)
- [멘트] "둘째는 비용입니다. 구어체·오타 때문에 매번 번역 LLM을 부르면 비용이 늡니다. 처음 보는 표현만 한 번 번역해 캐시에 저장하니, 같은 세션의 반복 질문에선 호출이 0이 됩니다. [적중률 __%, 호출 __→__회]."
- [반영] ⑥⑧②

### S8. 벽3 → 분석 → 해결: 실시간 수집 (Playwright + LLM URL 선택)
- [넣을 것] 막대그래프를 **"수집 성공률"** 기준으로(현재 bytes 비교는 약함). 흐름: `메뉴 수집 → LLM이 질문 정합 URL 선택 → 타겟 파싱`(run_pipeline 4단계와 일치).
- [⚠️ 숫자 라벨 정정] "309개"는 **수집된 메뉴 링크 풀**, 기본 크롤 상한은 `CRAWL_MAX_PAGES=20`. 둘은 다른 수치 — 라벨 구분. Playwright 미설치 시 requests 폴백이라는 점도 인지.
- [멘트] "셋째는 실시간 수집입니다. 대상이 JS로 동적 렌더링돼 정적 요청은 [성공률 __%]로 사실상 실패했습니다. Playwright로 렌더링한 뒤, 모은 메뉴 309개 중 질문에 가장 맞는 URL을 LLM이 골라 파싱하게 했습니다. [성공률 __%]."

## 3. 수치 근거 설계 (피드백 ②⑤⑪ — 가장 중요)

### 3-1. 원칙
- 숫자를 지어내지 않는다. `___`는 **실측**으로 채운다. 못 채우면 슬라이드에서 뺀다(빈 주장보다 안전).
- 태그: **[실측]** / **[추정]**(가정 명시) / **[측정예정]**.
- ⚠️ **선결 과제:** 33.3/70.0·38/80·45/5 가 실제 산출값인지 확인 필요. `YHS_eval_questions_seed.py`가 검증셋을 *만드는* 중으로 보임 → N이 실측인지 예정인지부터 확정. 이게 ⑤의 핵심.

### 3-2. 3층 지표

**A층 — 전체 시스템 품질 (N=___ 검증셋)** ← ⑤ 핵심
| 지표 | 정의 | 1차 | 4차 | 방법 |
|---|---|---|---|---|
| 종합 점수 | (정확성+관련성+완전성)/3/5×100 | 33.3 | 70.0 | N=___, 3축 0~5 |
| 답변 정확도 | 출처/사실 일치 | 38% | 80% | 동일 셋 |
| 환각률 | 근거 없는 진술 | 45% | 5% | 동일 셋 |
| 응답률 | 답변 생성 성공 | 88% | 75% | 동일 셋(안전정책 트레이드오프) |
- 반드시 명시: 셋 구성(카테고리 분포), 채점 주체, 0~5 루브릭.

**B층 — 솔루션별 효과 (ablation)** ← ⑪
| 솔루션 | before→after | 측정 |
|---|---|---|
| 벽1 DDE/재랭킹 | 정확도 ___→___% | 재랭킹 off vs on, 동일 셋 |
| 벽2 번역 캐시 | 적중률 ___%, 호출 ___→___회 | 세션 내 누적 곡선 |
| 벽3 크롤링 | 성공률 ___→___% | requests vs Playwright |

**C층 — 임계값 도출** ← ⑤ "유사도 연구 어디서?"
- ⚠️ **먼저 확정:** 코드에 임계값이 여럿 — 게이트 `min_top_score`(클래스 기본 0.17, 실행 기본 `from_env`=0.25), 재랭크 컷 `_MIN_CHUNK_SCORE=0.30`, 근거 최소 `2개`. **실제 채택값이 뭔지** 정하고 그 값을 스윕으로 설명.

| 임계값 | 정확도 | 환각 | 비고 |
|---|---|---|---|
| 낮음 | ___ | ___ | 잡음 유입 |
| **채택값** | ___ | ___ | **최적점** |
| 높음 | ___ | ___ | 정답 누락 |

### 3-3. 측정 우선순위
1. A층 평가 방법 문서화(숫자가 이미 있다면).
2. C층 임계값 스윕표(⑤ 방어 효과 최대) — 셋 그대로 임계값만 바꿔 재실행.
3. B층 캐시 적중률·비용(로그 기반, 비용은 [추정]+가정 명시).
4. B층 크롤링 성공률(대상 N개 중 성공 수).
