# YHS 기말 발표 기획안 (15분 기준)

> 목적: 6/10 피드백을 반영한 **발표 흐름 재설계 + 슬라이드별 구성안 + 발표 멘트 + 수치 근거 설계**.
> 이 문서로 방향 확정 후 → PPT 빌드 단계로 넘어감.

## 0. 먼저, 현재 초안의 약점 (직설적으로)

좋다고 넘어가기 전에 교수가 찌를 지점부터 정리함. 대부분 피드백과 일치함.

1. **3페이지 GraphRAG 슬라이드에 "Are you happy? / lollipop" 플레이스홀더 이미지가 그대로 박혀 있음.** 안 바꾼 게 티남. 피드백 ④대로 Neo4j는 별도 슬라이드 빼고 한 줄로.
2. **수식이 두 덱에서 서로 다름.** 중간발표: `score = 벡터유사도×0.6 + 키워드×0.4`, 임계값 0.17. 기말 초안: `Score = 0.60·S_Hybrid + 0.30·S_Keyword + 0.10·S_Recency`. 항이 2개→3개로 바뀌고 임계값 언급이 사라짐. 이거 그대로 두면 "어느 게 맞냐"고 바로 물어봄. → **하나로 통일하고 ⑦대로 각 항의 의미를 설명.**
3. **7페이지 캐시 슬라이드의 CPU 캐시 계층도(L1/L2/L3/DRAM) 이미지는 너희 시스템과 무관함.** 비유로 쓸 거면 "비유"라고 명시하거나, 실제 캐시 흐름도로 교체.
4. **11페이지 성능 그래프의 라벨 오류 가능성.** 33.3 / 56.7 / 70.0은 중간발표 슬라이드 20 기준 **최종(종합) 점수**임. **답변 정확도**는 38 / 74 / 80이었음. 기말 초안은 이걸 "정확도"로 라벨링함 → 라벨 정정 필요. (⑤가 정확히 이 출처를 물음)
5. **5페이지 병목 표가 전부 정성적 표현("품질 붕괴", "비용 폭주", "전면 실패")인데 숫자가 없음.** 피드백 ②⑪의 핵심 타격 지점. as-is 수치를 붙여야 함.
6. **9페이지 디버깅 버그 슬라이드(가변 임계값 변수 오염)는 빼야 함.** 피드백 ⑨: 코딩하다 난 버그는 발표 대상 아님.
7. **12페이지 "수치 근거 추가할 것"이 빈 슬라이드.** → 본 문서 3장에서 설계.

## 1. 전체 흐름 재설계 (피드백 ⑫ ⑬ 반영)

### 서사의 척추
피드백 ⑬이 흐름을 명확히 줬음:
> **문제인식 → 페르소나 → 파이프라인 → 성능 → 결론**,
> 그리고 그 안에서 **"중간발표 이후 → 어떤 문제 → 어떤 분석 → 이렇게 해결"**.

핵심은 기말 발표 = **"중간발표 이후 우리가 한 것"**의 이야기라는 것. 그래서:
- 문제인식·페르소나·구조 설명은 **빠르게 리캡**하고 넘긴다 (⑫ "구조 넘기 ← 페르소나"). 중간발표에서 이미 한 내용을 또 길게 하지 말 것.
- 시간의 대부분은 **각 문제마다 [발견한 문제 → 분석 → 해결]을 as-is/to-be로** 보여주는 데 쓴다 (⑫ as-is/to-be 절차 How, ⑥ 문제-해결 연결, ⑪ 분석 기반 변경 강조).

### 한 문장 메시지
> "중간발표 땐 **설계**가 끝났다고 봤다. 실제로 돌려보니 운영 환경에서 3개의 벽이 나왔고, 각각을 **수치로 분석해서 → 구조를 바꿔** 해결했다."

### 15분 슬라이드 배치 (≈12장, 장당 1~1.5분)

| # | 슬라이드 | 시간 | 역할 |
|---|---------|------|------|
| 1 | 표지 | 0:20 | - |
| 2 | 문제인식 + 페르소나 (1장 압축) | 1:00 | 빠른 리캡 (⑫⑬) |
| 3 | 중간발표 시점 = "설계의 이상" | 1:00 | 출발점 (⑬ "중간발표 하고→") |
| 4 | 실제 운영 3대 벽 (+as-is 수치) | 1:30 | 발표의 척추 (②⑪) |
| 5 | 문제1 → 분석 → 해결: 검색 품질 | 2:00 | ⑤⑥⑦⑧ |
| 6 | 문제2 → 분석 → 해결: 다국어 비용 | 1:30 | ⑥⑧② |
| 7 | 문제3 → 분석 → 해결: 실시간 수집 | 1:30 | ⑥⑧② |
| 8 | 통합 파이프라인 (as-is→to-be) | 1:00 | ⑩(선택), ⑫ |

## 2. 슬라이드별 구성안 + 발표 멘트

각 슬라이드: **[넣을 것]** / **[발표 멘트]** / **[반영 피드백]**

### S1. 표지
- [넣을 것] 제목, 팀명, 발표일. 부제만 "중간발표 이후 개선 보고"로 한 줄 추가.
- [멘트] "팀 유학생입니다. 오늘은 중간발표 이후 실제 운영하면서 마주친 문제들과, 그걸 수치로 분석해 해결한 과정을 보여드리겠습니다."

### S2. 문제인식 + 페르소나 (압축, 1장)
- [넣을 것] 왼쪽: 핵심 문제 한 줄("정보가 파편화 + 비자→취업→절차로 종속적"). 오른쪽: 페르소나 Li Wei 미니 카드(23세/중국/거주 6개월/한국어 약함). 길게 설명 X.
- [멘트] "문제는 중간발표에서 정의했습니다. 한 줄로 요약하면, 유학생 행정 정보는 기관별로 흩어져 있고 단순 FAQ가 아니라 강한 종속 관계를 가집니다. 저희 기준 사용자는 거주 6개월차 Li Wei입니다. (10초)"
- [반영] ⑫(구조·페르소나 빠르게 넘기기), ⑬(문제인식·페르소나)

### S3. 중간발표 시점 = "설계의 이상"
- [넣을 것] 기존 slide4 유지 (Graph DB / 삼중 라우터 / 다국어 매핑). 하단 문구 "이 정도면 모든 질의를 커버할 줄 알았으나…" 유지.
- [멘트] "중간발표 시점엔 지식 그래프 적재, Fast/Deep/Crawl 삼중 라우터, 다국어 매핑까지 **설계상으론** 다 됐습니다. 문제는 여기서부터였습니다."
- [반영] ⑬("중간발표 하고 →")

### S4. 실제 운영 3대 벽 ★발표의 척추★
- [넣을 것] 기존 3대 병목 표 유지하되, **각 행에 as-is 수치 1개씩 추가**:
  - Scale-out: "데이터 N배 증가 시 유사도 점수 평준화 → 정답 chunk 변별 실패" + `[측정: 정답 chunk가 top-k에 든 비율 ___%]`
  - Cost: "구어체·오타로 캐시 미스" + `[측정: 미스율 ___%, 쿼리당 LLM 번역 호출 ___회]`
  - Real-time: "JS 동적 렌더링으로 정적 수집 실패" + `[측정: 정적 requests 수집 성공률 ___% (목표 페이지 기준)]`
- [멘트] "운영에 올리자 3개의 벽이 나왔습니다. 검색 품질, 비용, 실시간 수집. 각각 **숫자로 먼저 측정**하고, 그 분석을 근거로 구조를 바꿨습니다. 지금부터 하나씩 보겠습니다."
- [반영] ② (슬라이드에 숫자), ⑪ (분석→변경), ⑥ (문제 제시)

### S5. 문제1 → 분석 → 해결: 검색 품질 (DDE + 하이브리드 리랭킹)
- [넣을 것] 3단 구조로:
  - **문제(예시)**: "'아르바이트 할 수 있어?' 질문에서 데이터가 많아지자 무관한 chunk가 상위로 올라옴" (⑥ 구체적 예시)
  - **분석**: 임계값 스윕 결과 → 0.17이 정확도/환각 트레이드오프 최적점. **N=100 자체 검증셋에서 산출**이라고 명시 (⑤가 묻는 출처)
  - **해결(How)**: DDE(홉 거리로 스코어 감쇠: Hop0=1.0, Hop1=0.5) + 통합 스코어링.
- [수식 설명 — ⑦ 필수] 슬라이드에 수식 + 한 줄 해설:
  - `Score = 0.6·S_Hybrid + 0.3·S_Keyword + 0.1·S_Recency`
  - "S_Hybrid: 벡터+그래프 유사도(주력, 0.6), S_Keyword: 정확 키워드 일치(오타/공백 보정, 0.3), S_Recency: 최신 공지 가중(0.1)."
  - ※ **중간발표의 `0.6/0.4` 2항 수식과 통일할 것.** 둘 중 실제 코드에 있는 걸로. (지금 불일치)
- [멘트] "첫째 벽은 검색 품질이었습니다. 데이터가 늘자 유사도 점수가 위로 평준화돼서, 예를 들어 아르바이트 질문에 엉뚱한 chunk가 1순위로 올라왔습니다. 그래서 검증셋 100개로 임계값을 스윕해 0.17을 잡고, 홉 거리로 점수를 감쇠시키는 DDE와 키워드·최신성을 결합한 재랭킹을 넣었습니다. 결과는 [정확도 __% → __%]."
- [반영] ⑤ ⑥ ⑦ ⑧ ②

## 3. 수치적 근거 설계 (피드백 ② ⑤ ⑪ — 가장 중요)

### 3-1. 원칙: 정직성
- **내가 숫자를 지어내지 않음.** 아래는 "무엇을, 어떻게 측정해 근거로 쓸지"의 설계임.
- 발표 전 각 `___` 칸을 **실측값**으로 채울 것. 채울 수 없는 칸은 슬라이드에서 빼는 게 낫다 (빈 주장보다 안전).
- 내부 관리용으로 각 수치에 태그: **[실측]** 측정 완료 / **[추정]** 산식 기반 추정(가정 명시) / **[측정예정]** 아직.

### 3-2. 3층 지표 프레임

**A층 — 전체 시스템 품질 (N=100 검증셋)** ← ⑤가 묻는 핵심
| 지표 | 정의 | 1차 | 4차 | 출처/방법 |
|------|------|-----|-----|-----------|
| 종합 점수 | (정확성+관련성+완전성)/3/5×100 | 33.3% | 70.0% | N=100, 3축 0~5 채점 |
| 답변 정확도 | 출처/사실 일치 | 38% | 80% | 동일 셋 |
| 환각률 | 근거 없는 진술 비율 | 45% | 5% | 동일 셋 |
| 응답률 | 답변 생성 성공 | 88% | 75% | 동일 셋 |
- **반드시 명시할 것 (⑤):** 검증셋 100개를 어떻게 구성했나(카테고리 분포), 누가 채점했나(사람 N명 합의 / LLM-as-judge), 채점 기준 0~5 루브릭. 이게 없으면 "그 숫자 어디서 나왔냐"에 답 못 함.

**B층 — 솔루션별 효과 검증 (ablation)** ← ⑪의 핵심 "분석→변경"
| 솔루션 | before → after 지표 | 무엇을 측정 |
|--------|--------------------|-------------|
| 문제1 리랭킹/DDE | 정확도 ___% → ___% (리랭킹 off vs on) | 같은 검증셋, 재랭킹만 토글 |
| 문제2 캐시 | 캐시 적중률 ___%, 쿼리당 번역 호출 ___→___회, 1000쿼리당 비용 ___→___원 | 쿼리 누적에 따른 적중률 곡선 |
| 문제3 크롤링 | 목표 페이지 수집 성공률 ___% → ___%, 파싱 메뉴 309개 | 정적 requests vs Playwright |
- 각 솔루션이 **전체 점수에 얼마 기여했는지**를 보이면 ⑪을 완벽히 충족. (단계별 표가 이미 이 구조 — 1→2 임계값, 2→3 모델교체, 3→4 데이터·수식)

**C층 — 하이퍼파라미터 도출 근거** ← ⑤ "유사도 연구 어디서?"
- **0.17 임계값 도출**: 검증셋에서 임계값을 0.05~0.30으로 스윕 → 정확도↑/환각↓ 트레이드오프 최적점이 0.17. 작은 표 또는 곡선 1개로 제시.

| 임계값 | 정확도 | 환각 | 비고 |
|--------|--------|------|------|
| 0.10 | ___ | ___ | 너무 낮음(잡음 유입) |
| 0.17 | ___ | ___ | **채택** |
| 0.25 | ___ | ___ | 너무 높음(정답 누락) |

### 3-3. 측정 우선순위 (시간 없으면 위에서부터)
1. **A층은 이미 있을 가능성 높음** (단계별 표). → 평가 방법만 문서화하면 끝.
2. **C층 0.17 스윕 표** — 발표에서 ⑤ 방어용으로 가장 효과 큼. 검증셋 그대로 임계값만 바꿔 재실행하면 됨.
3. **B층 캐시 적중률·비용** — 로그만 있으면 계산 가능. 비용은 "[추정] 가정: 번역 1회당 $X" 명시.
4. B층 크롤링 성공률 — 대상 페이지 N개 중 성공 개수로 단순 계산.
