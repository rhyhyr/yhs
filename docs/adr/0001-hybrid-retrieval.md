**상태:** 확정 (Accepted)  
**관련 문서:** [RFC-001](../rfc-001-hybrid-search-strategy.md)

---

## 컨텍스트

동아대학교 유학생 행정 안내 챗봇(YHS)은 비자·건강보험·기숙사·장학금 등 도메인 지식이 법령·학칙·공지 PDF에 흩어져 있다. 사용자 질문은 단어 검색이 아닌 문맥 이해가 필요한 경우가 많고, 개체 간 관계(예: "D-2 비자 → 건강보험 가입 시기")를 추적해야 정확한 답변이 가능하다.

초기 프로토타입은 벡터 검색 단독으로 구현했으나, 20개 eval 질문 기준 답변 성공률이 낮고 엉뚱한 청크가 상위에 오르는 문제가 반복 관찰됐다.

---

## 결정

**그래프 검색 + 벡터 검색 하이브리드 방식**을 채택한다.

| 구성 요소 | 구현 |
|-----------|------|
| 그래프 검색 | Neo4j — 개체(Entity)와 관계(Triple) 기반 탐색 |
| 벡터 검색 | SentenceTransformers — 문맥 유사도 검색 |
| 점수 병합 | `0.60 × base + 0.30 × keyword_overlap + 0.10 × recency` |
| 하한 컷 | score < 0.30 청크 제거, question_fit < 0.06 시 no_answer 처리 |
| 그래프 단독 부족 시 | 벡터 검색 추가 실행 후 병합 |

가중치 기본값(0.60 / 0.30 / 0.10)은 `threshold_sweep.py` 실험으로 도출했다.

---

## 고려한 대안

| 대안 | 기각 이유 |
|------|-----------|
| 벡터 검색 단독 | 법령 조항 간 관계 추적 불가. 비자 자격 간 비교 질문에서 정확도 저하 |
| 키워드 검색(BM25) 단독 | 비표준 표현("비자 늘리기" 등) 대응 불가 |
| 그래프 검색 단독 | 임베딩 없이 개체 인식 실패 시 결과 없음 |
| NetworkX 경량 그래프 | 확장성 부족. 청크-개체-관계를 한 트랜잭션으로 관리하기 어려움 |

---

## 결과

- 응답 소스가 추적 가능해져 `[출처: 파일명, p.N]` 인용 제공 가능
- 그래프 단독 실패 시 벡터가 보완하므로 no_answer 비율 감소
- Neo4j 의존성 추가로 로컬 개발 환경에 Docker 설정 필요

---

## 후속 결정 필요 사항

- 가중치 세 값(base / kw / rec)의 주기적 재조정 실험
- 그래프 없이 벡터만 사용하는 라이트 모드 제공 여부 (운영 비용 절감 목적)
