## 데이터셋 (N=100, 전체 사용)
`EVAL_QUERIES` 100개 전부 사용(id 필터 없음). 각 항목의 `query`, `gold`, `source`, `stratum`, `lang` 사용.
- 표준(in_db) 44 · 복합(complex) 31 · 미수록(uncovered) 12 · 다국어/구어체(dirty) 13
- 언어: ko 91 · zh 5 · en 4

## 측정 지표 (5개)
1. **답변 품질** = (정확성+관련성+완전성)/3, 각 0~5 (100점 환산 병기)
2. **환각률** = 환각 판정(1) 비율
3. **근거 적합률** = 근거가 결론 지지(Y) 비율
4. **지연시간** = p50 / p95 (초)
5. (선택) **최신성** — 구버전 문서가 DB에 같이 적재돼 있을 때만. 없으면 "미측정"으로 표기.

## 1단계 — 워밍업 (측정 전 필수)
콜드스타트(임베딩 bge-m3 로드, 중국어 번역 opus-mt 다운로드, Ollama 첫 로드)가 첫 질의 지연을 뻥튀기한다.
→ **측정에 안 쓰는 질문 2개**(한국어 1 + 중국어 1)를 먼저 돌려 모델을 다 올린 뒤, 그 결과는 **버린다.** 그 다음부터 측정 시작.

## 2단계 — 러너 작성 (답변 수집)
`backend/src/yhs/rag/query_runner.py` 의 `run_query_loop()` 은 대화형(`input()`)이라 그대로 못 쓴다.
흐름 재현은 `experiments/run_eval100.py` 에 이미 되어 있다. 재현 대상 로직은 `process_question()`.
- 초기화: `GraphStore`, `Embedder`, `RetrievalEngine`, LLM 클라이언트
  (`api/deps.py` 의 `AppState.create()` 가 같은 조립을 한다)
- 각 질문 `q`:
  1. `t0=perf_counter()`
  2. `result=engine.retrieve(q)` → `best_score`, `len(result.chunks)`
  3. `should_use_deep_path(...)` 로 deep 판정, deep이면 `runtime.py` 의 `run_deep_path()` 가 하는
     변형쿼리 병합 + (필요시) 웹크롤 재현
  4. `context=engine.build_prompt_context(result)` (+external_contexts)
  5. `answer=llm.generate_answer(q, context, result, web_context=...)`
  6. `latency=perf_counter()-t0`
  7. `sources=[c.source_file for c in result.chunks]`, `method=result.retrieval_method`, `path`
- 저장: `runs.jsonl` — `{id, stratum, lang, query, gold, answer, sources, latency, path, method}`

### ★에러 처리 (필수)
- **질문 1개당 try/except.** 한 질문이 실패(크롤러 타임아웃·번역 에러 등)해도 기록만 남기고(`error` 필드) **다음 질문 계속.** 절대 전체 중단 금지.
- 크롤러 호출에 타임아웃(예: 15초) 걸고, 실패 시 그 질문은 그래프/벡터 결과만으로 답.

## 3단계 — 채점 (gpt-4o-mini, LLM-as-judge)
OpenAI 클라이언트로 `gpt-4o-mini` 호출(`client.chat.completions.create`, `temperature=0`).
각 answer를 아래 프롬프트로 채점 → JSON 파싱 → `scores.jsonl` 저장.

주의:
- **미수록(uncovered)**: `gold`가 `"[크롤러]"`로 시작 = 정적 정답 없음. "정답"은 단정하지 않고 최신 확인/크롤러 경로 안내. 근거 없는 구체 수치 단정 시 `hallucination=1`.
- **다국어(zh/en)**: 질문과 같은 언어로 답했는지도 관련성에 반영.
- ★**JSON 파싱 방어**: 응답에서 ```json 코드펜스 벗기고 파싱. 실패하면 1회 재시도, 그래도 실패면 `error`로 기록하고 계속.

### 심판 프롬프트 (gpt-4o-mini)
```
당신은 엄격한 채점자다. 아래 답변을 정답 근거에 비추어 평가하라.
[질문] {query}
[질문 언어] {lang}
[정답 근거(gold)] {gold}
[시스템 답변] {answer}

규칙:
- accuracy: 정답 근거와 사실 일치 정도 (0~5)
- relevance: 질문에 직접, 질문과 같은 언어로 답하는 정도 (0~5)
- completeness: 핵심 항목 누락 없이 답한 정도 (0~5)
- hallucination: 근거에 없는 내용을 단정하면 1, 아니면 0
- grounded: 제시한 근거가 결론을 지지하면 "Y", 아니면 "N"
- gold가 "[크롤러]"로 시작하면, 구체 정답 대신 '최신 확인 안내'가 정답이다.

아래 JSON만 출력(코드펜스·설명 금지):
{"accuracy":0,"relevance":0,"completeness":0,"hallucination":0,"grounded":"Y","reason":"한 줄"}
```

## 4단계 — 집계
- 답변 품질 = mean((accuracy+relevance+completeness)/3) → 0~5, ×20=100점
- 환각률 = mean(hallucination)
- 근거 적합률 = (grounded=="Y")/N
- 지연 p50/p95 = latency 정렬 후 분위
- **전체 + stratum별(표준/복합/미수록/다국어)** 각각

## 정직성 규칙
- stratum별 N 작은 칸(미수록 12·다국어 13)은 비율에 생개수 병기("75% (9/12)"). 과대 일반화 금지.
- 미수록은 낮게 나오는 게 정상(크롤러 폴백). stratum별로 따로 보여준다.
- **EXAONE 기준 재측정값.** 예전 70%(Gemini·in-DB)와 직접 비교 금지.
- LLM 비결정성: 답변·심판 모두 `temperature=0`. 1회 실행(시간 되면 3회 평균).
- 보고서 각주에 심판 모델(gpt-4o-mini)·루브릭·실제 N 명시.
