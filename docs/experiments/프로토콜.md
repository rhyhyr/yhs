## 0. ★먼저 — 덱과 코드/실험기록 대조 (정직성 점검)★

N=100만 문제가 아님. 발표 전에 **반드시** 정리해야 할 불일치들:

| 항목 | 덱 주장 | 실제 (코드·실험.pdf) | 조치 |
|------|---------|----------------------|------|
| 평가셋 크기 | "N=100 기반 최적 임계값 산출" | 실험.pdf에 N 명시 없음. 종합점수가 0.5 단위(1.5~4.0)인 걸 보면 **소수 문항**일 가능성 큼 | **실제 N으로 정정.** 작아도 솔직하게 |
| 스코어 수식 | `0.60·S_Hybrid + 0.30·S_Keyword + 0.10·S_Recency` | `hybrid_score = 0.65·cosine + 0.25·keyword_overlap + 0.10·recency` (`vector_retriever.py:10`) | **실제 수식(0.65/0.25/0.10)으로 통일.** ⑦ 설명도 이걸로 |
| DDE (방향 거리 인코딩) | "Hop0=1.0, Hop1=0.5 스코어 반감" | **실재 확인됨.** `config.py:76` `DDE_SCORE_BY_HOP={0:1.0,1:0.5,2:0.25,3:0.125}`, `graph_retriever.py:76`에서 BFS 탐색 중 홉별 감쇠 적용 → triple 랭킹 | 그대로 발표 OK. **덱은 2단계만 보여주니 4단계 테이블로 보강**하면 더 강함 |
| 임계값 | "0.17이 N=100 최적값" | gate `min_top_score=0.17`(`agent_runtime.py:26`)은 실재. 단 4차 개선의 핵심은 **병합 통과기준 0.45→0.3, 그래프 청크 신뢰도 0.7→0.75** (실험.pdf p2) | 가짜 "N=100 sweep" 대신 **실제 튜닝 스토리**로 ⑤ 답하기 (아래 4장) |
| 최종 모델 | "Gemini 엔진 최적화 → YHS 최종" | `.env`: `RUNTIME_LLM=ollama`, `OLLAMA_MODEL=exaone3.5:7.8b`. git: "Gemini→Ollama(EXAONE) 전환" 커밋 존재. 즉 **70%는 Gemini로 측정**, 현재 시스템은 **EXAONE** | ⚠️ 어느 모델로 발표할지 확정 + **그 모델로 재측정.** 70%가 현재 시스템 값이 아닐 수 있음 |
| 정확도 그래프 라벨 | 33.3/56.7/70 = "정확도" | 실험.pdf: 33/56/70은 **종합 점수**, 답변 정확도는 38/74/80 | 라벨 정정 |

**핵심**: 너희 4단계 실험 자체는 솔직하고 탄탄해. 문제는 **덱에서 포장하다 사실과 어긋난 부분(N=100, DDE, 수식, 모델)**임. 교수 피드백 ⑤가 정확히 이 약한 고리를 가리킨 거고, 정정하면 오히려 신뢰가 올라감.

## 1. 새 실험셋 구축 (하이브리드)

### 왜 새로 짜나
실험.pdf 4차에 "**데이터셋을 데이터베이스 안에 있는 문서에 해당하는 질문으로 변경**"이라고 적혀 있음 = 기존 셋은 **DB에 답이 보장된 in-distribution 질문만**. 그래서 너희 차별점인 **크롤러 폴백·다국어 캐시가 평가에서 거의 안 돌아감.** 새 셋은 이 경로들을 일부러 건드린다.

### 4개 층 (각 층이 개선 하나를 검증)

| 층 | 질문 성격 | 예시 | 검증 대상 | 개수 |
|----|----------|------|-----------|------|
| ① 표준(In-DB) | DB에 답 있는 정상 질문 | "D-2 비자 연장 서류?" | Fast/Deep + 리랭킹 | 10 |
| ② 복합 | 비교·원인·예외 | "알바하면 보험료 올라?" | Deep path 확장 | 10 |
| ③ 미수록 | DB에 없는 최신·세부 질문 | 특정 학과 최신 공지 | **크롤러 폴백** | 10 |
| ④ 지저분/다국어 | 오타·구어체·신조어·중/영 | "freelance 돼?", 중국어 | **번역+캐시** | 10 |

→ **N=40** (시간 없으면 층당 5개 = N=20도 방어 가능). 발표엔 **실제 N을 그대로** 기재.

### 소스 (하이브리드) — "어디서 가져왔나"에 답할 수 있게 문서화
실제로 확인한, 인용 가능한 출처:

| 출처 | URL/위치 | 쓰임 |
|------|----------|------|
| Hi Korea 자주묻는질문(FAQ) | https://www.hikorea.go.kr/cnslt/faq/FaqListR.pt | 비자·체류·외국인등록 실제 질문 |
| 동아대 국제교류과 공지/안내 | https://dms.donga.ac.kr/global/7338/subview.do , https://global.donga.ac.kr/ | 학사·유학생 행정 질문, ③ 미수록용 최신 공지 |
| 너희 핸드북 | repo의 `동아대_유학생_행정생활_정보핸드북.pdf` | ① 표준 질문의 gold 근거 |
| 너희 크롤러 309개 메뉴 풀 | 시스템 로그 | 실제 도메인 어휘 |
| 커뮤니티(보조) | 에브리타임 동아대 게시판, 카카오 유학생 오픈채팅 | 구어체·실제 고민 톤 |

> 발표용 한 줄: "질문은 **Hi Korea FAQ·동아대 국제교류과 공지·자체 핸드북**에서 실제 항목을 추출하고, 페르소나 기반으로 오타·다국어 변형을 더해 구성했습니다. 출처별 개수: ___."

규칙:
- ③ 미수록은 **일부러 DB(보강된 15개 문서)에 없는** 최신 공지·세부 주제로 골라야 크롤러가 실제로 돈다.
- ④ 지저분/다국어는 ①②의 질문을 오타·구어체·중/영으로 paraphrase (캐시·번역 검증).
- 각 질문에 **출처 메모**를 달아두면 ⑤("어디서?") 즉답 가능.

### 크롤링은 별도 지표로 측정 (Fast/Deep와 분리)
크롤러는 폴백이라 일반 정확도에 섞으면 안 보임. 따로:

| 지표 | 정의 | 측정 층 |
|------|------|---------|
| 폴백 정답률 | 미수록 질문 중 크롤러가 **정답까지** 도달한 비율 | ③ |
| 수집 성공률 | 목표 페이지 렌더링·파싱 성공 비율 (정적 requests 대비) | ③ |
| **오발동률(false trigger)** | DB에 답 있는데 크롤러를 잘못 띄운 비율 | ①② |
| 폴백 지연 | 크롤러 경로의 추가 레이턴시(초) | ③ |

→ 오발동률·지연을 같이 재야 "크롤링이 멀쩡한 답을 망치진 않냐"는 질문에 방어됨.

### 포맷 — 기존 `experiments/zh_eval.py` 구조 재사용
이미 너희가 쓰던 형식이 있음:
```python
{"id": "v1", "query": "...", "expected_intent": "visa",
 "stratum": "in_db", "gold": "정답 근거 요약 + 출처 URL"}
```
`gold`(정답)는 공식 출처에서 미리 확정 → 채점 기준.

## 2. 채점 — LLM-as-judge (선택 반영)

### 설계
- **심판 모델은 답변 생성 모델과 분리.** 현재 답변이 EXAONE면 심판은 Gemini(또는 그 반대). 같은 모델이 자기 답 채점하면 편향.
- 루브릭은 기존 그대로: **정확성·관련성·완전성 (0~5)** + **환각 (0/1)** + **회피 여부(no_answer)**.
- 심판 프롬프트에 **gold(정답 근거)를 같이 제공**해서 사실 일치를 보게 함.
- **사람 스팟체크 20%**: 무작위 8개를 팀원이 직접 채점해 LLM 점수와 비교 → "LLM 심판이 사람과 일치"라는 한 줄이 방어력 큼.

### 심판 프롬프트 골격
```
[질문] {query}
[정답 근거] {gold}
[시스템 답변] {answer}
다음을 0~5로 평가하고 이유를 한 줄로:
- 정확성(출처/사실 일치) - 관련성(질문에 직접 답) - 완전성(핵심 누락 없음)
- 환각 여부(근거에 없는 진술이 있으면 1) JSON으로 출력.
```

## 3. before/after = Feature Flag Ablation ★Q3 답: 재현 "가능"★

git 스냅샷 필요 없음. 너희 코드에 이미 토글이 다 있음:

| 끄는 것 | 방법 (env) | 측정되는 효과 |
|---------|-----------|---------------|
| 하이브리드(리랭킹) | `ENABLE_HYBRID_MODE=false` (`feature_flags.py`) | 벡터-only 대비 정확도 Δ |
| 그래프 검색 | `ENABLE_GRAPH_SEARCH=false` | 그래프 기여도 |
| 번역/캐시 | `ENABLE_ZH_TRANSLATION=false` (`zh_eval.py`에서 사용) | 다국어 정답률·호출 Δ |
| 임계값 | `GateThresholds.from_env()`가 env에서 읽음 → 해당 env로 변경 | 통과기준별 정확도/환각 |
| 모델 | `RUNTIME_LLM=ollama|gemini|hf`, `OLLAMA_MODEL=...` | llama vs gemini vs exaone |
| 가중치 | `VEC_WEIGHT`, `KW_WEIGHT` (`web_search_client.py`) | 수식 가중치 영향 |

### 실행 패턴
```bash
# 전기능 OFF (baseline 재현)
ENABLE_HYBRID_MODE=false ENABLE_ZH_TRANSLATION=false python -m experiments.<eval> 

# 전기능 ON (최종)
ENABLE_HYBRID_MODE=true ENABLE_ZH_TRANSLATION=true python -m experiments.<eval>

# 기능 하나씩 켜며 단계별 기여 (실험.pdf 4단계 표의 진짜 버전)
```
→ 같은 새 질문셋으로 돌려서 **단계별 ablation 표** 생성. 이게 곧 before/after 비교표.

⚠️ **새 셋은 더 어려워서(③④ 포함) 절대 정확도가 옛 70%보다 낮게 나올 수 있음.** 정상임. **옛 70%(in-DB·Gemini)와 새 값을 직접 비교 금지** — 새 셋으로 전부 다시 돌리고, 옛 표는 "중간 과정"으로만.

## 4. 임계값 도출 — 실제 스토리로 ⑤ 답하기

가짜 "N=100 sweep" 버리고 **실험.pdf의 진짜 사건**을 쓰면 됨:
> "그래프에서 찾은 정답 청크의 점수 최솟값이 **0.42**인데 통과기준이 **0.45**라, **정답을 찾고도 키워드가 없으면 버려지는** 문제가 있었다. 그래서 통과기준을 **0.45→0.3**으로 낮추고 그래프 청크 기본 신뢰도를 **0.7→0.75**로 올려 정답 청크가 항상 기준을 넘게 맞췄다."

이건 "관찰→분석→조정"이 명확해서 ⑤·⑪을 동시에 충족. 원하면 지금 **통과기준 0.2~0.5 스윕**을 새 셋으로 재실행해 작은 표로 보강:
